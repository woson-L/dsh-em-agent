# 自定义频段与特殊需求

> **文档索引** › [配置面板](../README.md) › 自定义频段与特殊需求

配置面板里有两处可以自行增删条目：**② 频段与指标** 与 **③ 特殊任务**。
新增条目与预设条目走完全相同的链路（校验 → 生成指令 → 存储 → 恢复），不是附加的便签。

## 操作

- **新增**：点该区域下方的 `+ 新增频段` / `+ 新增特殊需求`
- **编辑**：新增后行内始终可编辑，改完即生效，不需要「保存」按钮
- **删除**：每行右侧的「删除」按钮（语义红，与页面编辑器里删除区块同一套约定）

预设的三个频段**不可删除**，只能启用/禁用——它们是图表的基准区间。
「隔离度要求」与「自定义性能指标」同理，属于固定项。

## 数据结构

存在 `cst-console-config-v1` 里，与既有字段同级：

```jsonc
{
  "fields": { /* 各表单字段，键为元素 id */ },
  "bandEnabled": ["band-24"],
  "bandState": { "2.4-2.48": { "on": true, "threshold": "-8", "custom": "",
                               "resOn": false, "resFreq": "", "resS11": "-15", "resCustom": "" } },

  // 自定义频段：预设 BANDS 是常量，自定义项单独存放，读取时由 allBands() 合并
  "customBands": [
    { "id": "band-c1", "key": "3.6-3.8", "label": "3.6 – 3.8 GHz",
      "range": { "lo": 3.6, "hi": 3.8 }, "custom": true }
  ],

  // 自定义特殊需求：与「隔离度要求」同构的一行
  "customSpecs": [
    { "id": "spec-c1", "name": "增益", "op": ">=", "value": "2", "unit": "dBi", "note": "" }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `customBands[].id` | 稳定标识，用于删除与 DOM id；序号接着已存最大值，不会撞号 |
| `customBands[].key` | 由范围数值派生（`3.6-3.8`），是 `bandState` 的索引键 |
| `customBands[].range` | `{ lo, hi }`，单位 GHz，必须 `0 < lo < hi` |
| `customSpecs[].op` | `"<="` 或 `">="`，生成指令时分别渲染成「不超过」/「不低于」 |
| `customSpecs[].name` | 为空的条目**不进入**任务指令（允许先加行后填写） |

## 兼容性

- **向后兼容** —— 老存档没有 `customBands` / `customSpecs` 两个键，读取时保持空数组，
  界面显示空态提示，其余配置照常恢复。
- **向前兼容** —— 新存档多出的键被老版本代码忽略，不会报错。
- **损坏数据** —— 结构不合法的条目直接丢弃（例如范围非数字、`lo >= hi`、
  非字符串的 `name` 会被归一为空串），不让一条坏数据把整个面板卡死。
- **跨版本** —— 两个数组只增不改，导入旧存档不会影响新字段。

以上四条都由 [回归测试](../dev/tests.md) 实际覆盖，不是推断。

## 校验规则

- 频率范围必须是正数，且下限小于上限
- 与**任何**既有频段（含预设）范围相同时会被拒绝并提示

> 重复判定用的是**数值比较**而不是 `key` 字符串比较：预设 key 写作 `2.40-2.48`，
> 而派生 key 写作 `2.4-2.48`，两者字符串不等却指向同一范围，只比字符串会漏判。
> 这是写测试时发现的一个真缺陷。
