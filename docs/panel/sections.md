# 配置区字段说明

> **文档索引** › [配置面板](../README.md) › 配置区字段说明

左栏六张配置卡，从上到下就是一次任务的输入顺序。带 **\*** 的是必填。

> 这一页是**字段参考**。如果你要找的是「怎么跑起来」，看
> [从 Store 安装](../start/store.md)；要找「自定义增删条目」，看
> [自定义频段与特殊需求](custom-items.md)。

---

## ① 工程配置（必需）

> 源 CST 工程**只读**，全部操作在工作副本上进行，不可覆盖源工程。

| 字段 | 说明 |
| --- | --- |
| 目标工程路径 **\*** | `.cst` 工程所在目录。可点「浏览目录…」用本机目录选择器 |
| 目标工程文件 **\*** | 文件名或相对路径。可「扫描 .cst」列出目录下真实工程并自动拼接为完整路径，或「选择文件…」直接选 |
| 任务工作目录 (cwd) | 新建会话的工作目录；工作副本创建于其下 `cst_runs/<run>_<日期>/`。留空时先用「工作区目录」填充；两者都空则**不带 cwd 建会话**，由 DSH 使用它自己的默认项目目录（启动 `dsh web` 时所在的目录），此时「工作副本」预览显示「（未设置任务工作目录）」 |
| 天线对象路径 **\*** | 天线所在组件/零件路径。**必须与 CST 工程树中的名称完全一致** |
| 基板对象路径 **\*** | 基板所在组件路径。同样必须与工程树一致 |

表单下方还有一行只读的「工作副本」预览，启动仿真后才会有值。

## ② 频段与指标

> 三频段可同时配置；每频段独立 S11 阈值与可选谐振点深度约束。启用后卡片橙色标识。

预设三个频段：`2.40 – 2.48 GHz`、`5.15 – 5.85 GHz`、`6.425 – 7.125 GHz`。
每张卡片：

| 控件 | 说明 |
| --- | --- |
| 启用勾选框 | 该频段是否参与优化。**默认只启用 2.4 GHz 频段** |
| S11 ≤ | 阈值下拉（-8 / -10 / -15 dB，或「自定义…」展开数字输入） |
| 谐振 | 勾选后追加「谐振频点深度约束」：指定某频点处的 S11 上限 |

预设频段**不可删除**（它们是图表与基准的固定区间），只能启用/禁用。

区域底部的 **`+ 新增频段`** 可添加自定义频段，频率范围可编辑、可删除 —— 见
[自定义频段与特殊需求](custom-items.md)。

## ③ 特殊任务

> 与普通 S11 目标不同视觉标识（橙色）；按需启用，均为可选；全部显式字段化，不隐藏在自然语言中。

| 项 | 说明 |
| --- | --- |
| 隔离度要求 | 勾选后填阈值（dB），表示 `S21 / S12 ≤ 该值`。**越负越好**：-35 dB 优于 -25 dB。多端口时才有意义 |
| `+ 新增特殊需求` | 自行添加「名称 + 比较方向 + 目标值 + 单位 + 备注」的一行，可编辑可删除 |
| 自定义性能指标 | 勾选后填写下方文本框，**每行一条**自由文本指标 |

预设项与自定义项都会进入最终任务指令的「# 4. 特殊任务」段。
名称留空的自定义行**不会**进入指令。

## ④ 迭代控制

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 最大迭代次数 **\*** | `15` | 整数，≥ 1；建议 5~50（超出只警告，不阻断） |
| 终止策略 | `两者任一` | `两者任一`（达标或达上限即终止）／`达标即止`／`达上限即止` |

## ⑤ 高级设置 / 锁定项

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 天线厚度 | `0.035` | 单位 mm。**固定约束，只读**——不提供自主设置，见[天线仿真固定约束](../constraints/README.md) |
| 天线材料 | `copper (annealed)` | CST 材料名 |
| 基板尺寸 | `36.3mm × 8mm` | 自由文本 |
| 局部网格 X / Y / Z | `0.1` | 单位 mm |
| 馈电阻抗 / 端口方向 | `50 Ω`（锁定） | 阻抗固定不可改；方向可选 X / Y / Z 轴 |
| 异常处理策略 | 见下 | 目前有 **缩放重试** 与 **强制细化网格** 两项，均默认勾选 |
| 预检补齐轮次 | `2` | 预检未通过时自动补齐条件的轮次上限（0~5）。用尽后**仍会自动开启仿真**，不再阻断；清空按默认 2 |

底部的 🔒 锁定项**不提供自主设置**：边界条件、全局求解器类型、全局网格划分策略
—— 一律沿用源工程的有效设置。

**场监视器不锁定**（2026-10-01 起）：模型可自行决定是否添加，不强制。
内激励端口相反——若工程中缺失或未连接，**必须**按上表的馈电类型 / 阻抗 / 方向补齐后才可求解；
预检未通过时会自动发起一轮「补齐后重检」，且**用尽轮次也不会阻断**，见[工程预检未通过会怎样](#工程预检未通过会怎样)。

> 异常处理策略决定模型在某一轮失败后怎么重试。两项都不勾选时，
> 指令里会写成「无（异常案例标记 blocked_case 并归档）」。

**天线厚度**是本卡唯一的**只读**字段，属[固定约束 FC1](../constraints/fc1-antenna-plane.md)：
厚度恒为 `0.035` mm，厚度方向即高度方向。`readConfig()` 取常量而非表单值；
`inpThickness` 不从 `localStorage` 恢复，因此存档中的历史值不会覆盖该约束。

| 字段 | 说明 |
| --- | --- |
| 自定义命令 | 每行一条，直接追加进任务指令的「# 11. 异常处理硬逻辑」段之后 |

## 工程预检未通过会怎样

点「启动仿真」后先跑一次**只读**预检（CST MCP 可用 / 源工程可读 / 工作副本可拷贝 /
天线基板路径存在 / 求解配置完整可解，**且激励端口建在全局坐标系 xyz 下**）。结论由模型输出的**结论行**判定（PASS / FAIL）。

**预检不会卡住你。** 未通过时先自动补齐所需条件，轮次用尽后**照样开启仿真**，
只在左栏留一条可见的警告：

1. 面板发出一条「补齐」指令：内激励端口按 ⑤ 的馈电类型 / 阻抗（50 Ω 固定）/ 方向补齐，
   **并且必须在全局坐标系 xyz 下建立或重建**（端口落在局部坐标系 uvw 时要删掉重建）；
   场监视器可加可不加；其余只做「使工程可求解」所必需的最小改动。
   **仍然禁止**修改源工程与 ⑤ 的锁定项。
2. 模型补齐后重新输出结论行，面板再判一次。补齐轮次由 ⑤ 的「预检补齐轮次」控制（默认 2，0~5）；
   设 0 表示不补齐、直接开启。
3. 轮次用尽（或结论读不出来）→ **不再阻断**：提示里写出**判定依据**（命中的结论行，或没有
   结论行时的判定词计数）与结论原文，然后照常发出任务指令开启仿真。

> 判定只认**结论行**（整行基本就是 PASS / FAIL，可带「结论：」前缀），不认正文里的条件句。
> 曾经的实现把「阻断原因」当失败信号，而预检指令本身要求模型 FAIL 时列出阻断原因，
> 于是一份四项全 PASS 的报告也被判失败并阻断 —— 现在由 `test/test-precheck.cjs` 锁住这个形状。

### 端口坐标系这一项要求「有证据才判 FAIL」

「端口建在全局 xyz」这条约束的**判定必须有证据**（回读端点坐标或端口所属坐标系；
CST 侧未必有现成的回读接口，允许用 VBA 查询）。拿不到证据时模型应写
「端口坐标系未能核对（缺少回读手段）」，**既不猜 PASS 也不猜 FAIL** ——
因为判 FAIL 会触发一轮自动补齐，而补齐的动作是「删除端口并按全局 xyz 重建」，
凭猜测删掉一个本来正常的端口，比不检查更糟。

### 预检**不**检查什么

- 工程树里除天线/基板之外的**其它实体**（例如 `component1/mainpcb`）：只核对配置的两个路径是否存在，
  不判断多出来的实体是否预期、也不就此提问；
- **ACIS 名称属性残留**（例如 `nantenna:` 前缀的旧名）：不检查、不报告、不影响判定；
- **场监视器**：可加可不加，缺失不算问题。

## 顶栏这几个数字分别是什么

任务控制条第二行是五个 KPI，**每个数字只认一个来源**：

| KPI | 来源 | 更新时机 |
| --- | --- | --- |
| **迭代进度** | 模型回传数据块里的 `round` / ④ 的「最大迭代次数」 | 每收到一次带 `round` 的数据回传；轮次**单调不回退**；从没收到过就是 `—` |
| **对话轮次** | 会话 `step/end` 事件计数 | 每完成一个代理步 +1。**它没有分母**——对话步数本来就没有上限 |
| 最差 S11 / 最佳候选 | 从模型回复文本里解析出的 S11 数值 | 出数才着色；未知保持 `—`（不对未知状态下好坏判断） |
| 状态 | 页面运行状态机 | 状态迁移时 |

> ⚠️ **「对话轮次」不是仿真迭代次数。** 早先的实现把 `step/end` 计数当作「迭代进度」的分子、
> 把最大迭代次数当分母，于是显示成「25 / 5」——分子、分母、标签是**三件不同的事**。
> 现在两者分开，各认各的来源；同一个计数在右栏事件流表头也叫「对话轮次」，全页一个名字。
> 这条由 `test/test-eventstream.cjs` 锁住（步数只动对话轮次、迭代进度只认 `round`、轮次不回退）。

## 事件流高度（可拖拽）

右栏首卡「事件流 / 状态可视化」底部的横条是**高度拖拽手柄**。
它不在配置表单里，但会写 localStorage（键 `chatview-height`），所以在这里一并说明。

| 操作 | 效果 |
| --- | --- |
| 按住并上下拖动 | 调整事件流区域的高度，**双向**生效 |
| 方向键 ↑ / ↓ | 每次 16px 微调；按住 Shift 为 48px |
| 双击手柄 | 复位：回到「自动填满剩余高度」的默认布局，并清除存档 |

范围：**110px ~ `max-height`（CSS 的 `62vh`，随视口高度变化）**，拖拽值会被钳到这个区间。

**拖拽状态与默认状态的区别**：

- **未拖过（默认）** —— 该卡是弹性块，自动吸收右栏剩余高度，保证两栏等高。
  代价是空数据时卡片底部会有一段空白。
- **拖过之后** —— 该卡与手柄切换到固定高度、不再参与拉伸。此时右栏会**短于左栏**
  （空缺留在右栏底部），这是你主动选择的结果。双击手柄即可回到默认。

> 修复记录：早期版本只写 `min-height`，而该卡的高度本身由 flex 布局决定，
> 于是**只能向下拖大、无法向上缩小**（`min-height` 只能撑大不能压小）。
> 现已改为写入确定高度并取消拉伸，双向可控。

## 运行监控区（S11 曲线 + 结果汇总表）

左栏下半部分。数据来自**会话文本的启发式采集**：从模型回复里解析「频率 … S11 = x dB」这类
成对的数值，仅作实时监控参考，**最终以结果导出为准**。

**曲线按轮次画，一轮一条**，不是把所有点连成一条线：

| 元素 | 含义 |
| --- | --- |
| 一轮一条曲线 | 先按数据回传里的 `round` 分桶，同一轮里每个频点（0.01 GHz 栅格）只留**最小值**——dB 越小越好，于是每条曲线就是「该轮最佳工程」的包络 |
| **绿色粗线** | 当前最佳轮次：它的「最差频点值」在所有轮里最小 |
| 蓝色细线 | 最新一轮（还没被判定为最佳时） |
| 灰蓝细线 | 更早的轮次 |
| 红点 | 只标**最佳轮次**的实际采集点，多轮点位叠在一起会糊成一片 |
| 图例 | `★ 当前最佳：第 N 轮（最差频点 x dB）`；还没有数据时显示「暂无曲线数据」 |

**轮次从哪来**：数据回传里的 `round` 决定频点归属哪一轮（详见
[数据回传协议](../editor/data-protocol.md)）。都还没回传过轮次时归到**第 0 轮**（基线）。

结果汇总表仍按**全部采集点**汇总（保守口径：早期较差候选也算进去），页脚会写明共几轮、
当前最佳是第几轮。曲线与表格口径不同，是有意的 —— 曲线看趋势，表格看最坏情况。

## 对话输入（往同一个会话里补话）

| 操作 | 行为 |
| --- | --- |
| **Enter** | 立即发送（同「发送」按钮） |
| **Shift + Enter** | 换行 |
| 中文输入法选字时的 Enter | **不发送**（`isComposing` / `keyCode 229` 放行） |
| 发送 | 走队列模式（`mode:"queue"`）：消息**追加**给大模型，**不打断**正在跑的预检或迭代；失败时输入框内容保留 |
| 清空对话 | **任务运行中**只清本地显示，会话与事件流继续跟踪（会先确认一次）；空闲/已结束时才真正解绑会话并把状态复位为 IDLE |

> 早先的实现里，回车只是往输入框里加一个空行（看着像发出去了），而「清空对话」会丢掉
> `chatSession` 并把状态改成 IDLE —— 正在跑的迭代从此无从跟踪。这两点由
> `test/test-monitor.cjs` 锁住。

## 配置怎么变成任务指令

「生成指令 / 启动仿真」会把上面六张卡的内容拼成一段结构化文本交给模型。拼装逻辑在
`readConfig()` → `buildInstruction()`。指令的段落顺序、以及如何把结果送回来，
见 [数据回传协议](../editor/data-protocol.md)。

指令里关于**激励端口坐标系**的口径只有一句、三处引用（`PORT_CS_RULE`）：
**必须建在全局坐标系（Global WCS，xyz）下，禁止局部坐标系 local WCS(uvw)**。
它出现在 `# 6 高级设置`、`# 7 刚性约束`，并在 `# 8 馈电端口注意事项`、预检项 5、
预检补齐轮里各重申一次。改动这一条时三处必须同步，别只改一处。

**天线仿真固定约束**（FC1 / FC2）使用同一手法，覆盖范围更大：`# 7` 拆为
`7.1 通用刚性约束` 与 `7.2 天线仿真固定约束`，7.2 由 `fixedConstraintLines(cfg)` 生成，
并在 `# 6`、`# 9`、`# 10`、预检与预检补齐轮重申；`# 10` 将其列为每轮固定动作。
下发位置清单见[约束是怎么落地的](../constraints/enforcement.md)，约束定义见
[天线仿真固定约束](../constraints/README.md)。

**工作副本覆盖口径**（`SAVE_OVERWRITE_RULE`）是第三条同手法的常量：迭代中把工作副本
保存回同一路径时必须带 `{"overwrite": true}`，由 `cst_save_project_tool` 先关闭仍占用
该路径的工程、再由 CST 覆盖 `.cst` 与其 `Result/` 目录；同时禁止模型自行删除工程文件，
禁止依赖任何 CST 交互式确认框。它出现在 `# 7.1`、`# 10 每轮流程`、预检补齐轮三处。
背景是 2026-10-02 实测到的「覆盖旧工程时 CST 要求人工确认删除旧结果」，根因与修复在
CST-MCP 侧，见[依赖总览](../start/dependencies.md)。

## 配置存在哪

除**异常处理策略**外，各字段都会随改随存到浏览器 `localStorage`（键
`cst-console-config-v1`）。策略复选框目前**不参与持久化**，刷新后回到默认（全选）。

完整的键清单与迁移方式见 [存储与迁移](storage.md)。
