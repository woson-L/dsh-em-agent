# How the Fixed Constraints Are Enforced

> **Docs index** › [Fixed constraints](README.md) › Enforcement

[FC1](fc1-antenna-plane.md) and [FC2](fc2-modification-scope.md) take effect only
through the surfaces listed here. This page enumerates them, so that changing one
surface without the others is detectable.

---

## Single source of truth

The wording is generated by one function in the panel rather than written out at
each use site.

| Name | Role |
| --- | --- |
| `ANTENNA_THICKNESS_MM` | `"0.035"` — the only place the thickness is written |
| `FC1_TITLE` / `FC2_TITLE` | the two bracketed titles |
| `fixedConstraintLines(cfg)` | returns the whole 7.2 block; `cfg` supplies 天线对象路径 and 基板对象路径 |
| `STATE_FIXED_IDS` | fields that must **not** be restored from `localStorage` (currently `inpThickness`) |

`cfg` values are interpolated, so the instruction always names the configured paths
rather than a printed default.

## Delivery surfaces

| Surface | Carries | Built by |
| --- | --- | --- |
| Task instruction `# 7.2 天线仿真固定约束` | the full block | `fixedConstraintLines(cfg)` |
| Task instruction `# 6. 高级设置` | `天线厚度：0.035 mm（固定约束 FC1，不可更改）` | constant |
| Task instruction `# 9. 设计自由度与优化策略` | design freedom bounded by 7.2 | literal |
| Task instruction `# 10. 自动化执行流程` | FC1 / FC2 self-check as a mandatory per-round step | literal |
| Pre-check instruction | standing clause above the check list | literal |
| Pre-check remediation instruction | clause repeated for the one writing round | literal |
| ⑤ 高级设置 · 天线厚度 | `readonly`, `aria-readonly`, pinned `0.035` mm | `readonly` attribute |
| `input[readonly]` styling | locked appearance; the value stays readable, unlike `disabled` | `src/styles.css` |

`readConfig()` returns `thickness: ANTENNA_THICKNESS_MM`, so no archived or
DOM-edited value can reach the instruction.

## Implementation

All of it is expressed as patches in [`build/build.ps1`](../../build/build.ps1)
(`P68a` – `P68l`); `src/baseline/` remains read-only, per
[the build rules](../dev/build.md). The build's reverse-reduction gate proves the
shipped panel equals *baseline + exactly these patches*.

## Regression coverage

[`test/test-constraints.cjs`](../../test/test-constraints.cjs) drives the real page
and asserts:

- the 7.2 block exists and interpolates the configured paths;
- FC1 carries the thickness, the substrate-face rule and the port-plane rule;
- FC2 carries the two-entry whitelist and the "no other Component" clause;
- the per-round self-check is present in `# 10`, in the pre-check and in the
  remediation round;
- the thickness field is read-only, and neither a DOM edit nor a planted
  `localStorage` archive can move it off `0.035`.

## Changing the constraints

These constraints are fixed by the user. Any change must cover all of the following
in one commit:

1. `fixedConstraintLines()` and the constants in `build/build.ps1`;
2. the literals in `# 6`, `# 9`, `# 10`, the pre-check and the remediation round;
3. the assertions in `test/test-constraints.cjs`;
4. this doc group.
