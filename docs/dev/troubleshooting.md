## 页面打不开 / 路由 404

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/em-agent` 返回 404 | 插件行没生效 | 检查 `cordis.patch.yml` 里的 `insert` 形式与缩进，重启一次 `dsh web` 确认 |
| 同上，且 patch 文件里明明写了 | 该行带了 `id` 指向不存在的条目 | DSH 对这种情况**只告警然后静默跳过**。改成无 `id` 的 `insert` 形式 |
| 保存了 patch 文件但路由没变 | 热加载只覆盖配置文件，不覆盖插件代码 | 路由行的增删会热生效；`index.js` 的改动**必须重启** |
| 页面能开，但按钮都是「复制指令」 | 用了 `file://` 直接打开 | 改用 `http://127.0.0.1:<端口>/em-agent` |
| **页面能开、界面正常，但点「启动仿真」报 401 / 传输失败** | 浏览器里没有 DSH 的登录 cookie。插件路由本身不鉴权（所以页面照常 200），但它调用的 `/api/*` 会校验 cookie | 先访问一次 `dsh web` 自动给出的主界面地址（形如 `http://127.0.0.1:3080/?token=…`，服务端 303 下发 `Path=/` 的 cookie），之后 `/em-agent` 即可正常使用 |
| **点「发送环境探测指令」报 `DSH 传输失败（HTTP 404）`** | RPC 协议不匹配：旧构建发点号式端点 `/api/session.create`，网关的 `claimsEndpoint` 要求端点按 `/` 切正好 2 段，于是**在任何业务逻辑之前**就回 404 | 2026-10-01 已修（补丁 P57：两段式端点 + `{ args: { request: … } }` 信封 + `session.prompt` 补 `requestId`）。回归覆盖见 `test/test-rpc.cjs`，契约见 [与 DSH 的 RPC 契约](dsh-rpc.md) |
| 右栏一直空着、看不到模型输出 | 会话事件流没连上（`/api/remote.mux` 上的 `session/follow`） | 2026-10-01 起已接通。若仍为空：刷新页面触发重连，并看左下角操作日志（`#logList`）里有没有「会话事件流出错：…」 |
| 点「浏览目录…」只弹一句「未开放目录选择器」 | `host.pickDirectory` 在当前 DSH 版本没有主机端点 | 手动填路径。这不是回归，旧写法同样只会拿到 404 |

## 任务跑起来之后

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| **激励端口建在了局部坐标系 local WCS(uvw)** | 模型在局部坐标系下建端口，坐标数值被当成全局 xyz 用 | 2026-10-01 已修（补丁 P67a–e）：任务指令 `# 6`/`# 7`、`# 8 馈电端口注意事项`、预检项 5、预检补齐轮四处同口径要求「必须建在全局坐标系 xyz」。若历史工程仍有 uvw 端口：让模型「删除端口并按全局 xyz 重建」，别手工改标注 |
| 曲线看不出哪一轮最好 / 像一条乱线 | 旧实现把全部采集点连成一条折线，多轮多候选混在一起 | 2026-10-01 已修（补丁 P67l–t）：按回传的 `round` 分桶，每轮每频点取最优，一轮一条曲线，最佳轮次绿色高亮。见 [运行监控区](../panel/sections.md) |
| **输入框里按回车没反应** | 旧实现只有「发送」按钮，回车只加空行 | 2026-10-01 已修（补丁 P67j）：Enter 发送、Shift+Enter 换行；中文输入法选字的回车不发送 |
| **发了消息之后任务好像断了** | 旧实现里「清空对话」会丢掉 `chatSession` 并把状态改成 IDLE | 2026-10-01 已修（补丁 P67h/i）：发送走队列模式（不打断），运行中清空只清本地显示且先确认。若状态被旧版改成了 IDLE：点「断线恢复」重新挂上会话 |
| **迭代中覆盖旧工程时，CST 弹出「删除旧结果」确认框，必须人工点掉** | CST-MCP 旧版 `save_project(overwrite=True)` 只删了 `.cst`，留下非空的伴随目录（`Model/` + `Result/`）。CST 以 `The project directory <dir> already exists and is non-empty` 拒绝；交互界面下就是那个确认框 | 2026-10-02 已修（CST-MCP 侧）：改为先关闭仍占用该路径的工程、再用 CST 原生 `allow_overwrite`，由 CST 自己覆盖 `.cst` 与伴随目录；面板指令同步固定了覆盖口径（补丁 P69a–d）。需升级 `cst-studio-suite-mcp` 并**重启 DSH** 才会加载新代码；现象消失前不要用「先删 `.cst`」绕过——那正是旧版的做法 |

## 顶栏一直显示 MCP 未连接

1. MCP 是否已注册到 DSH —— 见 [安装与检测 CST MCP](../start/mcp.md)
2. 页面「首次配置」里的 **MCP 服务名**是否与 `cordis.patch.yml` 里的 `serverName`
   **完全一致**（大小写、连字符都算）
3. 顶栏写的是「任务内探测」，它本身不代表掉线 —— 真正的连通性在任务执行时才验证

## 配置/区块数据不见了

| 现象 | 原因 |
| --- | --- |
| 换了端口或 host 后配置读不到 | localStorage 按 **origin** 隔离。`127.0.0.1:3080` 与 `127.0.0.1:8080` 是两份独立存储 |
| 「导出 JSON」后换地址导入，配置面板还是空的 | **导出只包含自定义区块**，不含面板状态（自定义频段、特殊需求、首次配置） |
| 清了浏览器数据后全没了 | 页面没有后端，这是唯一的数据源 |

详见 [存储与迁移](../panel/storage.md)。

## 构建失败

### `Unexpected token` / 一大堆语法错误（711 处）

**`build/build.ps1` 丢掉了 UTF-8 BOM。**

该脚本含大量中文补丁锚点。无 BOM 时 Windows PowerShell 5.1 会按 GBK 解码，
中文的尾字节会与紧随其后的引号配对、把引号「吞掉」，导致字符串失衡、整个脚本无法解析。
`pwsh` 7 没有这个问题，但多数机器没装。

处理：把文件另存为 **UTF-8 with BOM**。部分编辑器保存时会静默去掉 BOM，
所以每次大改之后都值得确认一次。

> 这不是理论风险：本仓库就踩过一次——711 处语法错误，脚本完全无法运行。

### 补丁命中 N 次（应为 1 次）

```
补丁 [Pxx ...] 命中 0 次（应为 1 次）——基线可能已变动
```

基线的锚点文本被改动了，或新补丁的 `old` 字符串写错。

**基线是只读的**（`src/baseline/`），不应该被修改。若确实需要改锚点，
要同步改所有引用它的补丁。

### 原有 id 丢失 / 已退役 id 不应出现

```
原有 id 丢失: foo, bar
已退役 id 不应出现在产物中: baz
```

这是**双向校验**：

- 想让某个 id 消失，必须把它登记进 `build/build.ps1` 的 `$script:retiredIds`
- 登记了却在产物里还在 → 说明退役没做干净

见 [构建与硬门禁](build.md)。

### 对比度门禁未通过

```
对比度门禁未通过: <选择器> 3.2:1 < 4.5:1
```

新增/修改的颜色组合不满足 WCAG AA。正文需 ≥ 4.5:1，非文本控件 ≥ 3:1。
检查是否用了新颜色而没有走既有令牌。

## 回归测试失败

1. **先确认服务在跑、URL 正确**。测试默认打静态地址，插件路由也能用。
2. **确认 Chrome 路径**。设 `CHROME_PATH` 指向实际安装位置。
3. **端口占用**。每个测试用固定的调试端口（9371/9373/9377/9379…），
   并发跑多个套件会撞端口，串行跑。
4. **看 `failures` 数组**，它直接给出「期望 vs 实际」。
   若失败的是「某元素不存在」，多半是构建产物没更新 —— 先重新构建。

## 页面渲染异常

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 整页空白 | 产物结构损坏（历史上曾因漏掉 `</style>` 导致） | 重新构建；构建的「结构断言」门禁会拦住这种情况 |
| 窄屏下按钮被拉成通栏 | `@media (max-width: 520px)` 给所有 `.btn` 设了 `flex: 1 1 auto` | 行内动作按钮需在该媒体查询里显式 `flex: none`（参考 `.topbar .btn-icon`） |
| 区块不显示 | 区块被禁用 | `enabled: false` 的区块不渲染也收不到数据 |
| **刷新后区块不见了** | 换了 origin（端口/host）、用了无痕窗口，或清了浏览器数据 | 区块本身是即时落盘的，不会自己消失。回到原地址即可看到；迁移用导出/导入 JSON。见 [页面编辑器](../editor/overview.md) |
| 以为只能加一个区块 | 每次点「新增区块」都是新开一个 | 数量不限，反复点即可。列表是一行一个 |
| 区块收到数据但没渲染 | `renderMode` 是 `custom` 而脚本没被执行 | 自定义渲染需要同时勾「允许执行脚本」 |
| 单元格没有颜色 | 判定文本不在着色白名单里 | 用 `PASS` / `FAIL` / `WARN` 等标准词，见 [区块格式规范](../editor/blocks.md) |

## 换了台机器

1. 前置依赖按 [从 Store 安装](../start/store.md) 重新装
2. CST 路径、MCP 地址要在**那台机器**的浏览器里重填（配置不跟着仓库走）
3. `build/build.ps1` 的 BOM 要确认（某些同步工具会丢）
